orders and orderItems act as a permanent transaction history. Even if a user buys 3 memberships, the database holds a complete receipt of every single purchase.

Stripe Checkout Flow

  • Click: User clicks "Order Standard".
  • Secure Lookup: Backend ignores the price sent by the browser and looks up the real price in Neon.
  • Pending: A row is created in the orders table with status: 'pending'.
  • Redirect: User is sent to Stripe's hosted checkout page.
  • Payment: User pays with test card 4242 4242 4242 4242.

The Webhook

A webhook is a "reverse API". Stripe pushes data to us when a payment completes.

// server/src/routes/webhook.js

// 1. Verify it's actually Stripe
const event = stripe.webhooks.constructEvent(req.body, sig, secret);

// 2. Mark the order as paid
if (event.type === 'checkout.session.completed') {
  await db.update(orders).set({ status: 'paid' });
}

The webhook is the ONLY authorized place to mark an order as paid.

Seamless UX: The Fallback

Webhooks can take 2–5 seconds to arrive. How do we stop the user from seeing a "Pending" screen?

Frontend Polling

Production Challenges

  • CORS & Cookies: Configured trust proxy on Render and SameSite=None to allow Vercel cookies.
  • Stripe API v2026: Removed the deprecated payment_method_types parameter.
  • Webhook Security: Used express.raw() to preserve the raw body for signature verification.
  • SPA Routing: Added vercel.json rewrites to stop 404s on /success.
