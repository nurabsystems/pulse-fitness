Technical Decision 01

Flexbox and Grid — deliberate choices

Flexbox — 1D layouts

  • Header + navigation
  • Hero section
  • Pricing cards (equal height)
  • Footer

Grid — 2D layouts

  • Trainer bio cards
  • About section (two columns)
  • Class schedule container

"Flexbox and Grid aren't competitors — they solve different problems."

07

Technical Decision 02

A design system via CSS variables

:root { --accent: #00E676; /* Pulse green */ --accent-dark: #00B85C; /* Hover state */ --dark: #0D1117; /* Background */ --dark-soft: #161B22; /* Card background */ --light: #F5F7FA; /* Text on dark */ --neutral: #8B949E; /* Muted text */ --border: #30363D; /* Subtle borders */ }

Changing the accent color sitewide: one line of code.

08

Technical Decision 03

Interactivity without JavaScript

Mobile hamburger menu

/* HTML */ <a href="#nav">☰</a> <ul id="nav">...</ul> /* CSS */ .nav-list:target { max-height: 500px; }

Thank-you confirmation

/* HTML */ <form action="#thank-you"> /* CSS */ #thank-you:target { display: block; }

Both use the CSS :target pseudo-class — pure HTML and CSS state management.

09

Challenge 01

Responsive table without horizontal scroll

❌ Wrong approach

Wrap the table in a scrollable container

Violates the "no horizontal scroll" requirement.

✅ Correct approach

Transform each row into a card on phone screens

@media (max-width: 600px) { tr, td { display: block; } td::before { content: attr(data-label); } }

Semantic table stays intact. Mobile gets stacked cards.
