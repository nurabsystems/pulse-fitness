Data-Driven Rendering

export const trainers = [
  { id: 'alex-rivera',
    name: 'Alex Rivera',
    specialty: 'HIIT', ... },
  { id: 'maya-chen',
    name: 'Maya Chen',
    specialty: 'Strength', ... },
]

No copy-pasted JSX.

Filter with useState

const [filter, setFilter] = useState('All')

const filtered = filter === 'All'
  ? trainers
  : trainers.filter(
      (t) => t.specialty === filter
    )

Derived state. No useEffect needed.

Controlled Component — RatingStars

<RatingStars
  value={rating}
  onChange={(v) => onRate(trainer.id, v)}
/>

RatingStars holds NO internal state.

The parent owns the value. The child fires the change.

State Lifting

App (owns ratings, userName)
 │
 ├── Trainers → TrainerCard → RatingStars
 │
 └── Contact (captures name)

Data down. Events up.

Multi-Step Quiz State

Three modes: entrance → quiz → result

const [mode, setMode] = useState('entrance')
const [step, setStep] = useState(0)
const [answers, setAnswers] = useState({})

Derived result computed from answers.

Name Capture + Personalization

  1. Contact form → name bubbles up
  2. App stores it → localStorage persists
  3. Next visit → Hero greets by name
  4. Same name flows into quiz result

Same pattern as ratings. Consistent.

Flexbox vs Grid

Grid — rigid 2D layouts (About section)

Flexbox — variable-count layouts (trainers, pricing)

justify-center handles orphan cards Grid can't.

Right tool for the right job.

What I Learned

  • Controlled components are the default, not the exception
  • Derived state eliminates whole classes of bugs
  • Lifting state makes the data flow obvious
  • key prop often beats useEffect for resetting
